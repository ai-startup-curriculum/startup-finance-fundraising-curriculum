# mod-111 — Finance Operations, Controls & Team Design

**From Founder-Bookkeeping to the Pre-IPO CFO Org**

**Track:** [Startup Finance & Fundraising](../../CURRICULUM.md)
**Stage:** SERIES-B / SERIES-C (with pre-seed / seed / Series-A groundwork)
**Hours:** 22 (9 chapters + 8 exercises + planned lab + planned quiz)

## What this module installs

Every previous module in this track produced a decision-grade artifact — three-statement financials, cohort unit-economics, driver-based models, cap tables, valuations, fundraises, term-sheet redlines, runway plans, board packs. This module installs the **operating infrastructure** those artifacts sit inside: the software stack that produces the ledger, the hiring plan that produces the team, the month-end close that produces the actuals, the audit that certifies them, the controls that make them defensible, the tax practice that harvests the credits, the compliance stack that keeps the company registered, and the IPO-readiness workstream that carries the whole thing to the S-1.

The through-line is the ownership boundary. This module covers finance-ops at the **CFO-decision level** — *which stack to buy, when to hire, when to audit, what controls to install, when to migrate, when to file* — not at the operator-mechanic level (which is a controller / staff-accountant discipline that would sit in a future `startup-accounting-controllership` track). A CFO who cannot make the migration call on time destroys the next raise; a CFO who can post the journal entries themselves is doing the wrong job. Both matter; only the first is this module.

Specifically:

- **Finance-ops stack selection by stage** — pre-seed / seed founder-bookkeeping (Mercury / Brex / Ramp on ops, QuickBooks Online / Xero on ledger, Gusto / Rippling on payroll, Airbase / Ramp on AP); Series-A outsourced-CFO or first controller; Series-B NetSuite migration; Series-C+ Coupa / Blackline / Workday Adaptive layer. The "which stack the company graduates onto next" call is a first-order CFO decision, not a back-office one.
- **First-ten hires sequence** — outsourced accountant / bookkeeper → outsourced or fractional CFO → first controller → first FP&A analyst → head of accounting → treasury lead → tax lead → head of FP&A → head of investor relations → CFO team-of-team — against stage triggers and against Carta / Pave comp benchmarks.
- **Month-end close design** — trial balance, accruals, deferred-revenue schedule, cost-of-revenue matching, expense classification, payroll reconciliation, cash reconciliation, close review; and the 5-business-day close target that Series-A and later require.
- **Audit-readiness** — the first outsourced audit (typically Series-B, board-triggered or pre-IPO), the audit-prep work the finance-ops team owns, PBC (prepared-by-client) list management, and the two-year audit-history requirement that IPO S-1 filings need.
- **SOX-lite financial controls** — segregation of duties as headcount allows, approval hierarchies for spend, procurement policies, corporate-card and expense-policy enforcement, wire-transfer controls — as the pragmatic pattern at Series-B before the full SOX regime at IPO.
- **R&D tax credits** — Section 41 research-credit qualification (permitted-purpose activities, the four-part test), the payroll-tax-offset election available to qualifying small businesses, the ongoing documentation practice, and when the credit meaningfully extends runway.
- **Sales-tax / VAT / registration compliance** — nexus determination (post-Wayfair economic nexus), state registration, marketplace-facilitator regime, EU / UK VAT, and the compliance stack (Avalara / TaxJar / Anrok) that a growth-stage SaaS needs.
- **IPO-readiness / dual-track** — the two-year audit history, PCAOB-registered auditor selection, financial-reporting close on a public-company timeline, SOX-404 remediation, S-1 drafting workstream, MD&A authoring, and the pre-IPO CFO role in choreographing the whole — with the transaction-execution mechanics themselves deferring *sideways* to [`startup-exit-curriculum`](https://github.com/ai-startup-curriculum/startup-exit-curriculum).
- **The ownership boundary** — the CFO-decision altitude this module operates at, and the operator-mechanic depth it explicitly does *not* teach.

## How this module fits

Directly depends on [`mod-101`](../mod-101-startup-accounting-foundations/) (the accrual mechanics the close and audit sit on top of), [`mod-103`](../mod-103-three-statement-model-and-driver-based-forecasting/) (the model the FP&A team maintains and reconciles to actuals), [`mod-109`](../mod-109-runway-management-and-bridge-financing/) (the runway math that decides when a hire is affordable and when a migration is on the critical path), and [`mod-110`](../mod-110-board-and-investor-governance-for-the-cfo/) (the board channel — including the audit-committee cadence — the audit-readiness workstream and controls program report into).

Directly feeds [`project-101-seed-to-series-a-fundraise-pack`](../../projects/project-101-seed-to-series-a-fundraise-pack/) (the finance-ops discipline that produces the diligence-ready actuals the pack presents) and the dual-track / IPO transaction pillar that formally lives in [`startup-exit-curriculum`](https://github.com/ai-startup-curriculum/startup-exit-curriculum) (which owns the transaction execution this module hands off to).

The module *does not* teach: the day-to-day bookkeeping mechanics an assistant controller or staff accountant runs (a future `startup-accounting-controllership` track would own that depth); the M&A / IPO / secondary transaction execution ([`startup-exit-curriculum`](https://github.com/ai-startup-curriculum/startup-exit-curriculum) owns transaction execution); the deep tax-code interpretation a startup tax attorney handles (specialist counsel territory); or the SOC 2 / ISO 27001 controls program that a security team runs alongside the financial-controls program covered here (belongs in a security / trust track). It teaches the CFO which decisions to make about the operating infrastructure, when to make them, and which primary source to check before making them.
